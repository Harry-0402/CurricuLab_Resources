Unit 3: Data Modeling

Unit Overview

Data Modeling is the process of organizing data from different tables and creating relationships between them to enable accurate analysis and reporting. In Power BI, data modeling helps combine data from multiple sources into a structured model, improving report performance and ensuring correct calculations.

Key Concepts

Data Modeling Introduction

Definition

Data Modeling is the process of creating relationships among different tables to organize data efficiently for analysis.

Key Points

  • Connects multiple tables.
  • Reduces data redundancy.
  • Improves report accuracy.
  • Supports advanced analysis and DAX calculations.

Example

Connecting Sales, Customer, and Product tables using common fields.

Relationship

Definition

A relationship is a connection between two tables using common columns (keys).

Key Points

  • Links data across tables.
  • Enables cross-table analysis.
  • Essential for report creation.
  • Helps create a unified data model.

Example

Customer Table Sales Table
Customer ID Customer ID

Customer ID acts as the common key.

Need for Relationships

Why Relationships are Required

  • Combine data from different tables.
  • Avoid duplicate information.
  • Create meaningful reports.
  • Enable filtering across tables.
  • Improve data consistency.

Example

Without relationships:

  • Customer data and Sales data remain separate.

With relationships:

  • Sales can be analyzed customer-wise.

Relationship Types (Cardinality)

What is Cardinality?

Cardinality defines how records in one table relate to records in another table.

One-to-One Relationship (1:1)

Definition

One record in Table A matches exactly one record in Table B.

Example

Employee Table Passport Table
One Employee One Passport

Characteristics

  • Rarely used.
  • Unique values on both sides.
  • No duplicate keys allowed.

One-to-Many Relationship (1:M)

Definition

One record in one table can be related to many records in another table.

Example

Customer Orders
One Customer Many Orders

Characteristics

  • Most common relationship type.
  • Primary key on one side.
  • Foreign key on many side.

Example

Customer ID = C101

Orders:

  • Order 1
  • Order 2
  • Order 3

All belong to Customer C101.

Many-to-One Relationship (M:1)

Definition

Many records from one table relate to a single record in another table.

Example

Many Sales Records
↓
One Product

Characteristics

  • Reverse view of One-to-Many.
  • Common in transactional databases.

Many-to-Many Relationship (M:M)

Definition

Many records in one table can relate to many records in another table.

Example

Students Courses
One Student → Many Courses
One Course → Many Students

Characteristics

  • More complex.
  • Can affect performance.
  • Often requires bridge tables.

Auto Detect Relationship

Definition

Power BI can automatically identify and create relationships between tables based on matching column names and values.

Advantages

  • Saves time.
  • Quick model creation.
  • Useful for beginners.

Limitations

  • May create incorrect relationships.
  • Requires verification.

Example

Customer ID present in both tables.

Power BI automatically creates the relationship.

Active and Inactive Relationships

Active Relationship

Definition

The default relationship used by Power BI during calculations and reporting.

Characteristics

  • Represented by a solid line.
  • Only one active relationship between two tables.

Example

Customer Table
──────►
Sales Table

Inactive Relationship

Definition

A relationship that exists but is not used automatically.

Characteristics

  • Represented by a dashed line.
  • Can be activated using DAX functions such as USERELATIONSHIP().

Example

Order Date Relationship → Active

Ship Date Relationship → Inactive

Best Practices for Data Modeling

Key Points

  1. Use One-to-Many relationships whenever possible.
  2. Avoid unnecessary Many-to-Many relationships.
  3. Keep table names meaningful.
  4. Remove unused columns.
  5. Verify Auto Detect results.
  6. Use star schema design.
  7. Maintain clean primary keys.

Star Schema

Definition

A data model where a central Fact Table is connected to multiple Dimension Tables.

Structure

Product
↓
Customer → Sales (Fact Table) ← Date
↓
Region

Benefits

  • Faster performance.
  • Easier analysis.
  • Better scalability.

Snowflake Schema

Definition

An extension of the Star Schema where dimension tables are further normalized.

Example

Country
↓
State
↓
City
↓
Customer

Advantage

Reduces redundancy.

Disadvantage

More complex than Star Schema.

Star Schema vs Snowflake Schema

Feature Star Schema Snowflake Schema
Complexity Simple Complex
Performance Faster Slightly Slower
Storage More Less
Maintenance Easier Difficult
Preferred in Power BI Yes Less Common

Important Definitions

  • Data Modeling – Organizing data through relationships.
  • Relationship – Connection between tables.
  • Cardinality – Type of relationship between tables.
  • Primary Key – Unique identifier in a table.
  • Foreign Key – Column referencing another table.
  • Active Relationship – Default relationship used by Power BI.
  • Inactive Relationship – Relationship requiring DAX activation.
  • Star Schema – Fact table surrounded by dimension tables.

Unit 3 Summary

Data Modeling is the foundation of Power BI analysis. It involves creating and managing relationships among tables, defining cardinality, and organizing data efficiently. Understanding relationship types, active/inactive relationships, Auto Detect, and schema design helps create accurate, scalable, and high-performance Power BI reports.
