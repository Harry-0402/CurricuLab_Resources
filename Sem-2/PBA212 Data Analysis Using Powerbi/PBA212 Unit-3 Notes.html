Unit 3: Data Modeling

Introduction

After data has been cleaned and transformed using Power Query, the next important step is Data Modeling. Data Modeling is the process of organizing data from different tables and creating relationships between them so that meaningful analysis can be performed.

In Power BI, data modeling helps users connect related tables, avoid data duplication, improve report performance, and create accurate calculations.

Without proper data modeling, reports may produce incorrect results and become difficult to manage.

Data Modeling Process

Import Data ↓ Identify Related Tables ↓ Create Relationships ↓ Validate Relationships ↓ Build Data Model ↓ Create Reports & Dashboards

Topic 1: Data Modeling Introduction

Explanation

Data Modeling is the process of defining how data tables are connected and how information flows between them.

A good data model:

  • Improves report performance.
  • Reduces redundancy.
  • Ensures data accuracy.
  • Simplifies analysis.
  • Supports advanced calculations.

Components of a Data Model

Component Purpose
Tables Store data
Columns Store attributes
Relationships Connect tables
Keys Establish connections
Measures Perform calculations

Example 1

A retail company stores Customer, Product, and Sales information in separate tables and connects them through relationships.

Example 2

A school maintains Student, Course, and Marks tables and links them for performance analysis.

Topic 3: Need of Relationship

Explanation

Relationships are required when data is distributed across multiple tables.

Why Relationships are Needed

  • Combine information from different tables.
  • Avoid duplicate data storage.
  • Improve database efficiency.
  • Enable accurate calculations.
  • Support filtering across tables.

Without Relationship

Customer data and sales data cannot communicate.

With Relationship

Customer data can be linked directly to sales transactions.

Example 1

A company analyzes which customers generate the highest revenue.

Example 2

A university tracks student performance across multiple subjects.

Topic 4: Relationship Types / Cardinality in General

Explanation

Cardinality defines how records in one table relate to records in another table.

Power BI supports different types of relationships.

Relationship Types

Type Meaning
One-to-One One record relates to one record
One-to-Many One record relates to many records
Many-to-One Many records relate to one record
Many-to-Many Multiple records relate on both sides

Topic 5: One-to-One Relationship

In a One-to-One relationship, each record in one table corresponds to exactly one record in another table.

Topic 9: Auto Detect Relationship

Explanation

Power BI can automatically identify relationships when tables contain matching fields.

Benefits

  • Saves time.
  • Reduces manual work.
  • Quick model creation.

Process

Import Tables ↓ Detect Common Fields ↓ Generate Relationships ↓ Validate Results

Topic 10: Create a New Relationship

Explanation

Users can manually create relationships when Power BI cannot detect them automatically.

Steps

  1. Open Model View.
  2. Select Manage Relationships.
  3. Click New.
  4. Select tables.
  5. Select matching columns.
  6. Define cardinality.
  7. Save relationship.

Example 1

Link Product ID between Product and Sales tables.

Example 2

Connect Student ID between Student and Result tables.

Topic 12: Make Relationship Active or Inactive

Explanation

Power BI allows multiple relationships between tables, but only one can be active at a time.

Active Relationship

Used automatically during report calculations.

Inactive Relationship

Stored but not used unless explicitly referenced.

Example

Topic 13: Delete a Relationship

Explanation

Relationships can be removed when they are unnecessary or causing incorrect results.

Reasons to Delete

  • Incorrect linkage.
  • Duplicate relationships.
  • Business requirement changes.

Steps

Model View ↓ Select Relationship ↓ Delete Relationship ↓ Confirm
